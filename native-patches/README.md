# MJobs scoped Startup source patch

`mjobs-bounded-start.patch` builds on the scoped patches below. It adds a protected one-primary MJobs restore mode with automatic dispatch off and no UI launch. The primary is derived from the original preserved snapshot; its revision includes the full mixed-project snapshot, and native restore rechecks that snapshot on each tick. The separate hub button requires an exact one-session confirmation, fresh quota and all MJobs sessions exited. The installed native source was backed up locally before editing. Its focused Startup and restore suites pass 406/406; hub tests pass 21/21. The patch contains only source and tests, and `git apply --reverse --check` succeeds against the installed native source.

The live one-session web test on 2026-10-28 reached native Protected Startup but made no AO resume submission. A historical branch-review record first blocked bootstrap; the branch-review check was then scoped to the exact selected manifest, retaining native review validation. The next attempt reached restore validation and found nine historical MJobs primary records in the raw snapshot, despite one eligible primary. The installed source now checks eligible native targets, its tests pass, and the paused controller was reloaded. That failed attempt left Protected Startup `uncertain` with `restoreStartAttempted:true`, `restoreStarted:false`. Native read-only Recheck returned pending because it could not prove an acceptable never-submitted binding. The hub blocks another Start until uncertainty is resolved; do not clear durable state or retry by bypassing Recheck.

`mjobs-scoped-startup.patch` records the reviewed changes to the installed `C:\Tools\AO-Fleet-Control` controller. It adds an optional `expectedProjectId=mjobs-luna` and 64-character `expectedManifestRevision` pair to Protected Startup. The adapter checks that every target belongs to MJobs and that the manifest revision is unchanged before bootstrap, immediately before native restore and before enabling dispatch. The read-only Startup preview reports `projectIds` and `manifestRevision`.

The patch was applied to the local controller source on 2026-10-28, then the controller was reloaded only after verifying no working or idle sessions, no enabled automatic dispatch and no active Startup. The live preview shows both `babytracker` and `mjobs-luna`; therefore the hub still refuses MJobs Start. The patch includes native regression tests. The installed `test-startup.js` and `test-startup-adapter.js` suite passed 396/396 on MulattoTechBox. No Start request was submitted.

This patch contains source changes only. It contains no saved manifest, runtime state, credentials or transcripts. Apply it to the matching baseline controller source with `git apply --check` first; review version drift before using it elsewhere. The local controller remains the runtime authority until its source is migrated into a reviewed package in this repository.

`mjobs-project-preview.patch` builds on the first patch. It adds a read-only derived `mjobs-luna` manifest and `GET /api/startup/mjobs-preview`. The original snapshot was backed up locally and its hash stayed unchanged. `mjobs-scoped-restore.patch` then adds scoped restore bound to the global snapshot hash, with membership and identity checks on each tick and fail-closed behavior after source drift. ## BabyTracker review assessment (staged)

`babytracker-review-lifecycle.patch` applies to `tools/fleet-control/` in the `MulattoTech/BabyTracker` source repository. It adds an explicit `assess-task` action for submitted tasks. The controller verifies an exact PR head revision, assigned file scope and an independent GitHub review by an owner, member or collaborator. Acceptance requires an approved, merged PR; revision request or rejection requires an unmerged change request. The PR body must cite the exact `MulattoTech/BabyTracker#<issue>` requirement. Receipts are durable, repeated revisions are rejected, and a third review must accept or reject. A revision request returns the task to proposed without dispatching it. The action retains BabyTracker's existing origin and per-process token checks.

The staged BabyTracker suite passes 109/109 tests. **This patch is not installed on the running BabyTracker controller.** Its active `babytracker-5` session is still draining; replacing or restarting the live controller would change that lifecycle state. Apply only after the session has a verified terminal outcome, back up the native source and state, run native tests, and restart with dispatch paused. `gh.exe` must have read access to the BabyTracker PR and review API; unavailable or incomplete evidence fails closed. The project-level acceptance placeholder remains unassessed; task-level receipts do not assert overall requirement acceptance.
